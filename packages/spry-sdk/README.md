# @spry/sdk

Spry contract SDK: `SpryRouter` swap calldata builders and a cached `SpryHook`
views client. Built on `viem`; depends on `@spry/config` and `@spry/fee`.

## SpryRouter calldata builders

All eight swap entry points (single/multi hop, exact-in/out, allowance/Permit2),
each returning a ready-to-send `{ to, data, value }` with the brief section 6.1
guards enforced before building:

- `recipient != router` (the router has no sweep, so funds would be stranded),
- `1 <= amount < 2^255`,
- `path.length >= 1` and adjacent hops differ,
- Permit2 paths are ERC-20-only (no native ETH leg),
- positive deadline.

`value` is computed for you: native-ETH input attaches the amount (`amountIn`
for exact-in, `amountInMax` for exact-out); Permit2 and ERC-20 swaps attach 0.

```ts
import { buildSwapExactInputSingle, spryPoolKey, buildSelfPermitAndSwap } from '@spry/sdk';
import { PoolTier } from '@spry/fee';

const key = spryPoolKey({ tokenA, tokenB, tier: PoolTier.BLUE_CHIP, hookAddress });
const swap = buildSwapExactInputSingle({
  router, key, zeroForOne: true,
  amountIn, amountOutMin, // size amountOutMin with @spry/slippage
  recipient, deadline,
});
// walletClient.sendTransaction(swap)  // { to, data, value }
```

Batch a permit and a swap into one signature via `multicall`:

```ts
const batched = buildSelfPermitAndSwap(router, { token, value, deadline, v, r, s }, swap);
// or buildPermit2AndSwap(router, owner, permitSingle, signature, swap)
```

Helpers: `spryPoolKey` (dynamic-fee key for a tier, currencies sorted),
`poolId` (the v4 `keccak256(abi.encode(poolKey))`), `sortCurrencies`, and the
raw `encodeSelfPermit` / `encodePermit` / `encodePermitBatch` / `buildMulticall`.

## SpryHook views client

```ts
import { createSpryHookClient } from '@spry/sdk';

const hook = createSpryHookClient((req) => publicClient.readContract(req), hookAddress);

await hook.getBlockWindow();              // read once, cached (immutable)
await hook.getPoolWindow(poolId);         // live { windowStart, signedCum }
await hook.windowCountdown(poolId, block); // blocksRemaining for the window widget
hook.getTierParams(tier);                  // from the bit-exact @spry/fee table
await hook.verifyTierParamsOnChain(tier);  // confirm the cache matches the contract
```

The reader is injected (a thin adapter over viem / wagmi), so the client is
testable without a live chain.

## V4Quoter client (execution pricing)

The authoritative pricing source (brief section 5): never price a trade from the
`@spry/fee` curve or the subgraph. The quote functions are nonpayable (they
simulate the swap and return), so they go through viem's `simulateContract`.

```ts
import { createSpryQuoterClient } from '@spry/sdk';

const quoter = createSpryQuoterClient(
  async (req) => (await publicClient.simulateContract(req)).result, // [amount, gasEstimate]
  quoterAddress,
);
const { amountOut } = await quoter.quoteExactInputSingle({ poolKey, zeroForOne: true, exactAmount });
```

To derive the implied current fee for the slippage model, pair the quoted `net`
with the zero-fee constant-product `gross` (from pool state via `@spry/fee`) and
feed both to `@spry/slippage`'s `impliedFeePips*`. The raw request builders
(`quoteExactInputSingleRequest`, ...) are exported for wagmi composition.

## StateView reader (pool state)

Reads a pool's `slot0` (sqrtPriceX96) and `liquidity` and derives the virtual
reserves via `@spry/fee`. This is the "gross" leg of the implied-fee preview:
the zero-fee constant-product output, paired with the Quoter's `net`.

```ts
import { createSpryStateViewClient } from '@spry/sdk';

const stateView = createSpryStateViewClient((req) => publicClient.readContract(req), stateViewAddress);
const { reserve0, reserve1 } = await stateView.getVirtualReserves(poolId);
```

## Fidelity

The router and hook ABIs in `src/abi/` are vendored **verbatim** from
`spry-contracts/abis/` (generated, not hand-typed). The builder tests decode
their own output with `decodeFunctionData` against that ABI, so every calldata
is verified to match the real contract interface and argument order. `poolId` is
checked **against the real on-chain `PoolIdLibrary.toId`** via a fixture
generated by `tools/contract-diff` (`pool-ids.csv`).
